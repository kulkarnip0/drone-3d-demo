1. What this demo is trying to envision

The goal is not only a code demo. The goal is to build a visual mental model of a modern autonomous drone system. The browser-based drone-3d-demo can act as a mission visualization and concept demonstration layer, while a real backend such as ardupilot-swarm-sim or real hardware provides flight dynamics, autopilot state, sensor feeds, and mission execution.

GCS

Human decision layer

The GCS should show mission state, map, drone health, sensor detections, and allow high-level commands such as assign area, inspect asset, hold, land, or return.

Companion

Autonomy layer

The companion computer runs perception, local planning, mission logic, AI reasoning, and safe command generation. It talks to ArduPilot through MAVLink.

Flight controller

Safety-critical control

ArduPilot handles arming, modes, EKF, attitude control, position control, motor output, failsafes, landing, and RTL.

3. Public 3D vision example: ground vehicle dataset

This video is included as a visual example of what 3D vision/perception looks like on a ground vehicle: synchronized camera imagery, dense geometry, road surface understanding, and sensor-based reconstruction. The same perception concepts are useful when imagining drone autonomy, except the viewpoint changes from road-level to aerial/oblique viewpoints.

Source: CARD / CARIAD Road Dataset public website video. Embedded by URL, not re-hosted. Verify the dataset/video license before commercial reuse.
Why this belongs here

What to observe

  • Camera image as the human-readable scene view.
  • LiDAR/depth-style geometry as machine-readable 3D structure.
  • Road profile, bumps, potholes, and terrain as physical world features.
  • How perception output can become map updates, alerts, or navigation constraints.

For drones, the equivalent idea is: aerial camera + depth/SLAM + object detection + map reasoning → mission decisions.

  ↕ MAVLink telemetry and commands
Companion Computer

Flight Controller
Important design rule: the web UI should not directly control motors. It should send high-level mission commands. The companion and flight controller enforce safety.

6. Foundation models in the loop

Vision-language

Scene understanding

Describe observed scene, classify friendly/unknown/enemy assets, explain anomalies, and assist operators.

Detection/segmentation

Object-level perception

Find vehicles, persons, buildings, landing zones, roads, obstacles, smoke, or damaged areas.

Depth / 3D

Geometry reasoning

Estimate terrain, height, free space, occlusion, line-of-sight, and safe approach paths.

Planner assist

Mission decisions

Suggest search patterns, prioritize assets, summarize risk, and propose safe next actions.

The foundation model should advise and interpret. The flight controller remains responsible for safety-critical stabilization and failsafe behavior.

7. 3D environment building

The 3D world should grow slowly from a simple visual demo into a tactical mission sandbox. 

Stage 1: ground plane + drone path
Stage 2: terrain, buildings, roads, trees
Stage 3: friendly assets and base station
Stage 4: unknown objects and dynamic vehicles
Stage 5: enemy/threat assets and restricted zones
Stage 6: sensor FOV, detections, uncertainty, communication range
Stage 7: live backend connection to ArduPilot SITL / Gazebo
