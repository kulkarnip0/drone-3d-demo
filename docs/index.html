1. Vision

This project is not only a code demo. It is a visual concept space for explaining how a real drone autonomy system can be built gradually. The browser demo can show a 3D mission world, while the real autonomy stack can be connected later through a backend simulator or real drones. 

Operator / GCS
   ↓ mission intent, supervision, map view
Companion computer
   ↓ perception, planning, local autonomy
Flight controller / ArduPilot
   ↓ safe control, stabilization, motor outputs
Drone body + sensors
   ↓ camera, IMU, GPS, range, telemetry
3D world / mission environment
   ↓ friendly assets, unknown objects, enemy assets, terrain

2. Drone component showcase

Physical system

What the autonomy stack controls

  • Frame: mechanical body carrying all components.
  • Motors and propellers: generate lift and attitude control.
  • ESCs: convert controller outputs into motor power.
  • Battery and power module: supply energy and voltage/current telemetry.
  • Flight controller: runs ArduPilot/PX4-style safety and stabilization logic.
  • Companion computer: runs AI/perception/planning logic.
  • Sensors: camera, GPS, IMU, barometer, range sensor, optional LiDAR.
  • Telemetry radio/network: connects drone to GCS and swarm peers.

3. GCS, companion computer, and flight controller

GCSmission planning, map view, operator decisions
↔
Companion computerAI, perception, local planning, task execution
↔
Flight controllerArduPilot/PX4, stabilization, failsafes

The companion computer should not directly control motors. It should send safe high-level commands through MAVLink, while the flight controller handles stabilization, arming checks, failsafes, and motor outputs. 

GCS command:       inspect area A
Companion action:  plan path, run perception, track objects
MAVLink command:   waypoint / velocity / guided target
Flight controller: attitude control, position control, motor outputs

4. Networking view

MAVLink

Control and telemetry language

MAVLink carries heartbeat, mode, command, position, altitude, battery, mission, and status messages.

GCS link

Operator connectivity

The GCS may connect over telemetry radio, Wi-Fi, LTE/5G, or a routed IP network.

Swarm link

Drone-to-drone awareness

Drones can exchange health, pose, task status, and local detections through a swarm coordination layer.

Backend bridge

Web visualization

A backend can translate live telemetry into WebSocket messages consumed by this browser-based 3D demo.

Real / simulated drone telemetry
   → backend bridge
      → WebSocket / REST state stream
         → drone-3d-demo browser visualization

5. Foundation models and autonomy

Foundation models should be used as reasoning and perception support, not as direct motor controllers. A practical design is to let foundation models interpret camera views, maps, language commands, and object context, while verified planners and flight controllers execute safe motion.

Perception

What is in the scene?

Detect vehicles, people, buildings, landing zones, roads, obstacles, and assets.

Reasoning

What does it mean?

Classify friendly, unknown, enemy, high-risk, mission-relevant, or ignored objects.

Planning support

What should we do next?

Suggest inspect, track, avoid, report, hand over, or request operator confirmation.

6. 3D environment building

The 3D world can be built slowly: first terrain and drones, then friendly assets, then unknown objects, then enemy assets, then sensor fields of view and detections. 

Stage 1: Terrain + drone positions
Stage 2: Friendly assets: base, convoy, landing pad, operators
Stage 3: Neutral/unknown assets: buildings, vehicles, people, obstacles
Stage 4: Enemy assets: hostile drone, jammer, suspicious vehicle
Stage 5: Sensor model: camera cone, detection probability, tracking state
Stage 6: Mission reasoning: inspect, avoid, classify, coordinate

8. Roadmap from demo to real system

1. Browser-only 3D visualization
2. Add map builder and asset placement
3. Add friendly / unknown / enemy asset states
4. Add simulated camera FOV and detection logic
5. Connect to backend state stream
6. Connect backend to ArduPilot SITL / Gazebo
7. Add companion-computer local agent
8. Add foundation-model perception/reasoning module
9. Add real drone telemetry through MAVLink
10. Keep GCS as supervisory interface, not unsafe direct motor control
