04 · ROADMAP

Centralized → hybrid → decentralized

Phase 1 · Global coordination

Each UAV produces a local belief. The GCS merges them and assigns tasks. Cloud inference can emulate early local-belief producers.

Phase 2 · Hybrid sharing

UAVs begin exchanging beliefs directly. The GCS supervises the mission rather than being the only information hub.

Phase 3 · Local decisions

Each UAV can take selected authorized decisions using its own belief and messages from neighbors. No permanent leader is required.

Phase 3 is the target architecture, not an already validated capability. Temporary disagreement between UAVs must be handled; peers do not always share a perfectly synchronized global picture.

05 · THE INVESTOR ANSWER

Why not simply leader–follower?

Leader–follower centralizes coordination around one agent, which can simplify implementation but creates dependency on that agent and the links to it. Kshatriya's target approach avoids a permanent leader: each UAV maintains an independent view of the mission and can share compact observations with its neighbors.

We address two bottlenecks at the representation level: data transfer volume and the time spent waiting for centralized decisions. Instead of continuously transmitting video, we communicate small descriptions of what each UAV knows.

“Move the information needed for a decision—not the whole image.”

This does not remove all delays. AI inference time, stale beliefs, network partitions, and conflicting decisions still need engineering solutions. We will test communication load, time to decision, task coverage, and behavior during link loss against centralized and leader–follower baselines.
